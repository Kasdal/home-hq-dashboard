# Deploy on the NAS

The NAS pulls a built site from GitHub. It does not build, and GitHub never
connects into the home network. The repository is public, so the NAS needs no
token.

## What the NAS serves

```text
~/homehq/
  repo/              shallow clone of the gh-pages branch
  releases/
    <sha>/           one built site per release
    bootstrap/       placeholder page
  current -> releases/<sha>
  data/              private JSON files, mounted at /sitedata and /data
  photos/            image files for the slideshow (in data/photos)
  nginx.conf
  pull.sh
  photos.py
  api.py
  pull.log
```

Two containers run from a private Docker network named `homehq`:

- `homehq-web`: `nginx:alpine`, published on port `8088`. It serves the site
  and proxies `/api/` to the API container.
- `homehq-api`: custom image `homehq-api:local` from `Dockerfile.api`, no
  published port. It serves shopping, bin state, photo uploads and recipes.
  The image adds Tesseract, Poppler, Pillow and Liberation fonts for recipe
  text extraction and PDF thumbnails.
- `homehq-llm`: `ollama/ollama`, no published port. It runs Qwen2.5 1.5B for
  the manual recipe parser. The model unloads after two idle minutes.

`~/homehq/data` is mounted read-only in the web container at `/sitedata` and
read-write in the API container at `/data`. A deploy swaps the `current`
symlink, so data files stay in place.

## First setup

1. Copy this folder to the NAS, for example to `~/homehq-setup`.
2. Run the installer:

```bash
bash ~/homehq-setup/install.sh
```

The installer does these things:

- Creates the directories, the placeholder page and a sample shopping list.
- Creates the `homehq` Docker network.
- Builds the `homehq-api:local` image with Tesseract, Poppler, Pillow and
  Liberation fonts.
- Starts the API container.
- Starts the `homehq-llm` container and pulls Qwen2.5 1.5B once.
- Starts `nginx:alpine` as `homehq-web` on port `8088`.
- Adds a crontab entry that runs `pull.sh` every 5 minutes and `photos.py`
  every 10 minutes.
- Pulls the first release if `gh-pages` exists.

Run it again after a change to `nginx.conf`, `pull.sh`, `api.py`,
`photos.py` or `Dockerfile.api`. The containers are replaced, and the cron
entries are not duplicated. The first image build takes a few minutes. Later
builds use the cached layers. The Ollama image is 8.5 GB and the model is
986 MB. Later runs reuse the model volume.

## Port

Port `8088` must be free. To use another port:

```bash
PORT=8090 bash ~/homehq-setup/install.sh
```

## Data files

Put the private JSON files in `~/homehq/data`. The page requests them from
`/data/`. All are optional. A missing file shows an empty state.

| File | Shape |
| --- | --- |
| `config.json` | `{"place":"...","latitude":52.0,"longitude":-7.0,"timezone":"Europe/Dublin","catName":"...","theme":{"lightStart":"06:00","darkStart":"18:00"}}` |
| `shopping.json` | See below |
| `tasks.json` | `{"items":[{"text":"...","list":"Shopping","done":false}]}` |
| `photos.json` | Album config, see below |
| `bins.json` | Bin schedule and alert, see below |
| `state.json` | Bin confirmations, written by the API |
| `controls.json` | `{"controls":[{"id":"lights","label":"Lights","url":"http://.../run","icon":"L"}]}` |
| `nest.json` | Indoor temperature, written by `nest.py` |
| `nest-credentials.json` | Nest login secrets, in `~/.config/homehq`, see below |
| `recipes.json` | Recipe metadata and extracted text, written by the API |
| `recipes/files/` | Recipe images, PDFs and text files |
| `recipes/thumbs/` | 600 px recipe thumbnails, generated by the API |

Keep `config.json` out of the public repository. It holds the home location.

`controls.json` entries must accept `POST`. The frame sends a bodyless POST and
treats any 2xx or 3xx answer as success.

### Shopping list

The installer writes a sample list on the first run. The API reads and writes
the same file:

```text
GET  /api/shopping   -> the list
POST /api/shopping   -> replace the list
```

The write uses a temporary file and `os.replace`, so a reader never sees a
half-written list. The API runs as the owner of `~/homehq/data` and is not
published to the network. Only nginx can reach it.

Schema:

```json
{
  "rev": 1,
  "stores": [
    { "id": "tesco", "name": "Tesco" },
    { "id": "lidl", "name": "Lidl" }
  ],
  "items": [
    {
      "id": "bananas",
      "name": "Bananas",
      "note": "Bunch, not too ripe",
      "qty": 1,
      "category": "Produce",
      "store": "any",
      "done": false
    }
  ],
  "usuals": [
    { "name": "Milk", "category": "Dairy & Eggs" }
  ]
}
```

`store` is `any`, `tesco` or `lidl`. An `any` item counts towards every store.
`category` is one of Produce, Bakery, Dairy & Eggs, Meat & Fish, Pantry,
Frozen, Drinks, Household, Other.

The page polls every 30 seconds. It pauses polling for 5 seconds after a local
change and while a text field has focus, so a phone edit does not overwrite an
edit in progress.

If the API is down, the page keeps working from `/data/shopping.json` and a
local backup. Changes stay on that screen until the API returns.

### Photos

`photos.json` is the album config, not the photo list:

```json
{
  "albumUrl": "https://photos.app.goo.gl/...",
  "refreshMinutes": 60,
  "intervalSeconds": 20
}
```

The `photos.py` job runs every 10 minutes. It fetches the share page when the
refresh interval has passed, parses the image URLs, downloads them at
1920x1080 into `photo-cache/`, removes photos that left the album, and writes
`photos-index.json`. The page reads the index. `intervalSeconds` controls the
slideshow.

If the album cannot be read, the last cache stays. The card shows the cached
photos with a small "Cached" tag, or a friendly message if there is no cache.

#### Why not the Google Photos API

Since 31 March 2025 the Library API only returns albums that the app itself
created, and `photoslibrary.readonly` is removed. Shared-album methods return
`403 PERMISSION_DENIED`. The Picker API needs a person to open a picker and
select photos, which cannot run unattended.

Source: https://developers.google.com/photos/support/updates

The share-page importer is therefore unofficial. Google can change the page
format. All parsing lives in `google_album.py`. If it breaks, the log shows
`album error: no photo URLs on the share page` and the display keeps the
cache.

Limits of this approach:

- Only the first batch of photos is present in the HTML. Very large albums may
  not expose every photo without a browser.
- Google may show a consent page in the EU. If it does, the log says so.
- The image URLs are public while the album is shared.
- Video items show as their still frame.

#### Upload from a PC

Open this link in a browser on the home network:

```text
http://<nas-address>:8088/upload/
```

Drag photos onto the page, or choose files. The page sends each file to the API,
and the API writes it to `~/homehq/data/photos`. JPEG, PNG and WebP are accepted,
up to 20 MB each. The page lists the uploaded photos and can remove one.

Uploads join the slideshow index immediately. `photos.py` rebuilds the index
from `data/photos` plus the album cache every 10 minutes, so uploads stay after
a rebuild. The frame reloads the index every 5 minutes.

The API endpoints:

```text
GET    /api/photos        -> {"photos":[{name,size,modified,url}],"maxBytes":...}
POST   /api/photos?name=  -> raw image body, one file per request
DELETE /api/photos?name=  -> remove one uploaded file
```

Only LAN clients can reach these endpoints, because `nginx.conf` allows private
address ranges only. There is no login. Any device on the home network can
upload or remove a photo.

#### Local folder

Put JPG, PNG or WebP files in `~/homehq/data/photos`. Nested folders work.
Uploaded files land in the same folder. Uploads show first, newest first, then
the album cache. Keep the files small: about 1600 pixels on the long side.

To sync a Windows folder to the NAS, use rclone:

```bash
rclone sync "C:\Users\you\Pictures\Frame" nas:/home/kas/homehq/data/photos --progress
```

Run it on a schedule with Task Scheduler. `rsync` over SSH works too.

A shared Google Drive folder is more reliable than a shared Google Photos
album, because Drive has an official API and a public folder link. It still
needs a small importer, but the format is stable. The local folder plus rclone
is the most reliable option.

### Cooking and recipes

The page is at `#cooking`. It has a search field, a card grid and a full-screen
recipe view. To add a recipe, drop a file on the page or use "+ Add recipe".
The accepted types are JPEG, PNG, WebP, PDF, TXT and MD. The limit is 20 MB per
file. One file makes one recipe. The recipe view uses the same single-column
document for all types: image, PDF, text and manual.

Recipe files live in `~/homehq/data/recipes/files`. Thumbnails live in
`~/homehq/data/recipes/thumbs`. The metadata lives in
`~/homehq/data/recipes.json`:

```json
{
  "rev": 1,
  "recipes": [
    {
      "id": "145390fb",
      "title": "Grandma's Soup",
      "titleAuto": false,
      "tags": ["soup", "winter"],
      "notes": "Use beef stock.",
      "ingredients": ["2 onions", "1 carrot"],
      "steps": ["Chop the vegetables.", "Cook slowly."],
      "file": "Grandma-Soup-145390.md",
      "type": "text",
      "mime": "text/markdown",
      "size": 64,
      "addedAt": "2026-11-08T12:36:00",
      "thumb": "",
      "text": "Grandma Soup\n\n- 2 onions...",
      "textSource": "file",
      "textStatus": "ready",
      "textAt": "2026-11-08T12:36:00",
      "structureStatus": "ready",
      "structureSource": "llm",
      "structureAt": "2026-11-08T12:36:30"
    }
  ]
}
```

The API creates the entry when the file lands. The title defaults to the file
name. A rename changes the JSON only, not the file name.

Text extraction runs in a background worker in the API container:

- TXT and MD files are read directly.
- Images use Tesseract OCR with English and Croatian.
- PDFs use `pdftotext` first. If the text is short, the first 10 pages are
  rasterized and OCR'd.
- Text is capped at 20,000 characters. A job times out after 120 seconds.
- Pending jobs are retried at startup and every 60 seconds.
- A failed job keeps the recipe file and sets `textStatus` to `failed`.

After the text is ready, a second worker sends up to 4,000 characters to the
same local LLM. It stores `ingredients`, `steps` and `notes`, and sets
`structureStatus` to `ready` or `failed`. The prompt keeps quantities, uses
metric units only, and puts calories and macros in Notes. The full OCR text
stays in `text`.
The background worker runs one parse at a time. A manual parse has priority
over queued background work. The structure step uses the same Qwen2.5 model.

The page polls `/api/recipes` every 30 seconds. The search matches title, tags,
notes, ingredients, steps and text. The structure appears after the job
finishes. A failed structure keeps the raw text and shows a retry button.

Endpoints:

```text
POST   /api/photos?kind=recipe&name=      -> raw file body, creates a recipe
POST   /api/photos?kind=recipe-file&name= -> upload a photo only
POST   /api/recipes/parse                 -> parse free text with the local LLM
POST   /api/recipes/manual                -> create a manual recipe
POST   /api/recipes/structure?id=         -> retry the structure step
GET    /api/recipes                       -> {"rev":...,"recipes":[...]}
POST   /api/recipes                       -> update fields and replace a photo
DELETE /api/recipes?id=                   -> remove the entry, file and thumbnail
```

`POST /api/recipes` takes only the editable fields. The server keeps the file
and text fields from its own copy. The last write wins for title, tags and
notes.

#### Manual recipes and the local LLM

The Cooking page has a "Paste recipe" button. It opens a form with a large text
area, an optional photo and tags. Paste any recipe text up to 4,000 characters.
The text can come from any web page or note.

The button `Dodaj uz pomoc AI modela` sends the text to the local LLM. The API
asks for a JSON object with `title`, `ingredients`, `steps` and `notes`. The
model runs with a JSON schema, temperature 0, 3 threads and a 4,096 token
context. A short recipe takes about 10-20 seconds. A long web page can take
about a minute. The prompt keeps the full ingredient quantity and unit,
converts to metric units only, and puts calories, macros and servings in Notes.

The response fills an editable preview. The user fixes any mistake, then saves.
The save uploads the photo (if any) through `kind=recipe-file`, then creates the
manual recipe. The photo upload does not create a recipe by itself.

A manual entry has `type: "manual"`, `ingredients` and `steps` arrays, an
optional photo, and a formatted `text` for search. The recipe view uses a
single column: photo, title, meta, tags, Ingredients, Preparation, Notes.

The model is Qwen2.5 1.5B Q4. The `homehq-llm` container has no published port.
The model loads on the first parse, and unloads after two idle minutes. Idle RAM
for the container is about 100-200 MB. A parse uses about 1.5-2 GB RAM and all
four CPU cores for about 20 seconds. Use `LLM_THREADS=3` in the API to leave one
core free. The Ollama image is 8.5 GB and the model is 986 MB. The model volume
is `~/homehq/llm`.

If the parse fails, the add fails. The form keeps the text and shows an error.
The user can retry. There is no silent fallback to Notes. The `llm.enabled`
setting in `/data/config.json` turns the feature off. The page hides the button,
and the API returns 503.

The parse endpoint has a 180 second timeout in nginx. A 4,000 character paste
takes longer than the normal 15 second API timeout, so it has its own location
block.

#### Automatic structure for uploaded recipes

When `llm.autoStructure` is true, the API structures uploaded recipes too:

- After OCR finishes, up to 4,000 characters go to the LLM.
- The model returns title, ingredients, steps and notes.
- The original file and the full OCR text stay.
- The title changes only when `titleAuto` is true, which means the file-name
  title is still in use. A user rename sets `titleAuto` to false.
- The user can edit ingredients and steps for file recipes in the same form.
- A failed structure keeps the raw text and shows "Retry structure".
- `structureStatus` is `pending`, `ready`, `failed` or `none`.
- The background worker runs one parse at a time. Manual parses have priority.
- The API drops AI items that do not share enough words with the source text.
  This stops invented steps. The view shows "AI structure. Check the original
  text." until the user edits the recipe.

The recipe view uses one layout for every type:

- A photo or image at the top.
- Title, meta and tags.
- Ingredients, Preparation and Notes sections.
- An "Original PDF" panel on a PC. The Android WebView hides the object and
  says the preview is not available.
- A collapsible raw text panel. For images and PDFs it shows the OCR text. For
  TXT and MD files it shows the file text.
- A missing file shows a "File missing" tag and keeps the metadata.

The settings:

```json
"llm": {
  "enabled": true,
  "autoStructure": true
}
```

`enabled` is the master switch. `autoStructure` controls the background step
for uploaded files. Set it to false to keep the raw text only. The manual
"Paste recipe" form still needs `enabled`.

The API image is built from `Dockerfile.api`. It adds about 100 MB to the image.
Only the API container can read the recipe folders. The web container serves
them read-only at `/data/recipes/`, because they are under `data/`. There is no
login. The nginx allow list keeps the page on the private network.

#### AI setup and rebuild

Components:

- `homehq-llm`: `ollama/ollama:latest`, no published port, network `homehq`,
  volume `~/homehq/llm:/root/.ollama`. Current image digest:
  `sha256:0e59999e0e8f9fd4e704bd788a89b7e4cad399367fb1365f8c102ac662288761`.
  The image is 8.5 GB.
- Model: `qwen2.5:1.5b`, Q4_K_M, 986 MB, model ID `65ec06548149`, context
  32768, Apache 2.0.
- API defaults: `LLM_URL=http://homehq-llm:11434`,
  `LLM_MODEL=qwen2.5:1.5b`, `LLM_TIMEOUT=180`, `LLM_THREADS=3`,
  `MAX_MANUAL_TEXT=4000`.
- Request: `POST /api/generate`, `stream:false`, `format` JSON schema,
  `temperature:0`, `num_ctx:4096`, `keep_alive:2m`.
- The prompt, schema and support check are in `deploy/api.py`.

The API starts the model on the first parse. The model unloads after two idle
minutes. The API sends one parse at a time. Manual parses have priority.

Fresh rebuild:

1. Install Docker on the NAS.
2. Copy `deploy/` to `~/homehq-setup`.
3. Run `bash ~/homehq-setup/deploy/install.sh`.
4. The installer pulls the Ollama image, starts `homehq-llm`, pulls
   `qwen2.5:1.5b`, builds `homehq-api:local`, and starts nginx.
5. Restore the private files: `data/config.json`, `data/recipes.json`,
   `data/recipes/files`, `data/recipes/thumbs`. The model cache is
   `~/homehq/llm`. The model is fetched again if the cache is empty.
6. Check:

```bash
docker exec homehq-llm ollama list
curl http://127.0.0.1:8088/api/recipes
curl -X POST http://127.0.0.1:8088/api/recipes/parse \
  -H 'Content-Type: application/json' \
  -d '{"text":"Milk, 200ml. Mix and serve."}'
```

7. Keep `llm.enabled` and `llm.autoStructure` in `/data/config.json`.

The installer uses the `latest` Ollama tag and the `qwen2.5:1.5b` tag. For an
exact rebuild, pin the image digest and model version.

Disk: about 9.5 GB for the Ollama image and model, plus about 100 MB for the
API image. Memory: about 1.5-2 GB during a parse. The container idles at about
100-200 MB. Hardware tested: Intel N100, 4 cores, 7.5 GB RAM, AVX2.

The `homehq-llm` container has no published port. Pasted text stays on the NAS.
The model does not call a cloud service. The model and image are not in git.

### Bin schedule and alert

`bins.json` is optional. The defaults are Thursday pickup, alternating from
12 November 2026 (black), and an alert from 00:00 on the pickup day:

```json
{
  "weekday": 4,
  "alertStart": "00:00",
  "alertDayOffset": 0,
  "referenceDate": "2026-11-12",
  "referenceBin": "black",
  "endDate": null,
  "exceptions": [
    { "date": "2026-12-24", "bin": "black", "replaces": "2026-12-25" },
    { "date": "2027-01-01", "skip": true }
  ]
}
```

- `weekday`: 0 Sunday to 6 Saturday.
- `alertStart` and `alertDayOffset`: use `-1` and `"18:00"` for an evening
  reminder on the day before.
- `exceptions`: a shifted pickup on any date, a different bin, or `skip`.
  `replaces` removes the normal pickup for that date.
- `endDate`: stop after this date.

On the pickup day the card pulses until someone taps "Bin is outside". The
confirmation goes to `state.json` through `POST /api/state`, so every screen
agrees. A new date has no confirmation, so the alert starts fresh.

```text
GET  /api/state   -> {"bins":{"2026-11-12":{"confirmedAt":"..."}}}
POST /api/state   -> {"bin":{"date":"2026-11-12","confirmedAt":"2026-11-12T07:42:00"}}
```

### Nest thermostat

`nest.py` reads the indoor temperature every 5 minutes and writes `nest.json`.
It uses the unofficial Nest web API, the same one the Nest app uses. Google can
change it at any time. This is not the official Device Access API and needs no
$5 fee.

Secrets live in `~/.config/homehq/nest-credentials.json` with mode 600. Never
commit it, and never put it in `data/`: nginx serves that folder on the LAN.

Google account, made or migrated after August 2019:

1. Use a Firefox private window. Chromium browsers copy a device-bound session
   that stops working after a few hours.
2. Open `home.nest.com` and sign in. Turn off Enhanced Tracking Protection for
   the site if the sign-in loops.
3. In Developer Tools, Network tab, filter `issueToken`. Open the request.
4. Copy the request URL. That value is `issue_token`.
5. Copy the `Cookie` request header value. It must include `SID=`. That value
   is `cookies`.
6. Close the private window without signing out.

```json
{
  "type": "google",
  "issue_token": "https://accounts.google.com/...",
  "cookies": "SID=...; HSID=...; ..."
}
```

Legacy Nest account, not migrated to Google:

1. Sign in at `home.nest.com`.
2. Open `https://home.nest.com/session`.
3. Copy `access_token` from the JSON text.

```json
{ "type": "nest", "access_token": "b..." }
```

Run it, then check the output and the log:

```bash
mkdir -p ~/.config/homehq
chmod 700 ~/.config/homehq
chmod 600 ~/.config/homehq/nest-credentials.json
python3 ~/homehq/nest.py
cat ~/homehq/data/nest.json
tail -5 ~/homehq/nest.log
```

The installer adds the 5-minute cron. Cookies expire. If the log shows an
authentication error, extract the values again and replace the cookies. The page
hides the INSIDE block when `nest.json` is missing, and keeps the last value when
a poll fails.

### Tasks and controls

These files have no generator. Write them from another system, or edit them by

## Backup

The dashboard data goes off-site every night at 03:30. The copy is plain files
in Google Drive, so any file opens straight from the Drive web page.

- `backup.sh` copies `~/homehq/data` and the live scripts with rclone. rclone
  is a single binary in `~/.local/bin`. It needs no root.
- The Nest credentials are not copied. They stay in `~/.config/homehq` on the
  NAS.
- The remote is `gdrive:homehq-backup-plain`, scope `drive.file`. rclone sees
  only the files it creates.
- Layout: `daily/YYYY-MM-DD`, `weekly/YYYY-Www`, `monthly/YYYY-MM`.
- Retention is 7 daily, 4 weekly and 12 monthly copies.
- The weekly copy runs on Sunday. The monthly copy runs on the first day of the
  month. Both are server-side copies, so they cost no upload.
- The LLM model and the release folders are left out, because they rebuild.
- The log is `~/homehq/backup.log`. It rotates at 1 MB.

### First setup

1. Run `rclone authorize "drive"` on a PC with a browser.
2. Put the token in `~/.config/rclone/rclone.conf` on the NAS, mode 600.
3. Run `~/homehq/backup.sh` once.

### Check and restore

```bash
~/.local/bin/rclone lsd gdrive:homehq-backup-plain
~/.local/bin/rclone lsf -R gdrive:homehq-backup-plain/daily/2026-11-08
tail -20 ~/homehq/backup.log
```

Copy one file back and compare it:

```bash
mkdir -p /tmp/restore
~/.local/bin/rclone copy \
  gdrive:homehq-backup-plain/daily/2026-11-08/data/shopping.json /tmp/restore
diff /tmp/restore/shopping.json ~/homehq/data/shopping.json
```

Or open the folder in the Drive web page and download the files by hand.

### Limits

- The copy is not encrypted. Google and anyone with the account can read it.
  Keep the account password strong and use two-step verification.
- The rclone build uses the shared rclone client ID. Google retires that ID
  during 2026. Make a personal client ID before it stops. See
  https://rclone.org/drive/#making-your-own-client-id
- The backup is a second copy, not a mirror. A deleted Google account loses the
  data.
- The old encrypted restic repository is still at `gdrive:homehq-backup`. It is
  not updated. Delete it when the plain copy has run for a while.

## Rollback

```bash
ls -1dt ~/homehq/releases/*
ln -sfn ~/homehq/releases/<old-sha> ~/homehq/current.new
mv -Tf ~/homehq/current.new ~/homehq/current
```

## Stop

```bash
docker stop homehq-web homehq-api homehq-llm
docker rm homehq-web homehq-api homehq-llm
crontab -e   # remove the pull.sh, photos.py, nest.py and backup.sh lines
```

## Network access

`nginx.conf` allows private address ranges only and denies every other client.
The API has no published port. Do not forward port `8088` on the router.
